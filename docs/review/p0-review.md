## 2. 阻断问题（必须修正才能进入实现）

### B1 · 换型时间不占资源时间轴，"硬约束零违反"是自证

**证据**（已复现）：R1 空闲 08:00–20:00，A1（60min，family FA）排 08:00–09:00，B1（120min，family FB）紧接 09:00–11:00。FA→FB 的 60 分钟换型应当占用 09:00–10:00，实际被 B1 直接压上。

**根因**：`setup` 只体现为 `cursor + setup` 的起点偏移，`[start-setup, start]` 从未写入空闲区间；且 `_prev_family` 取的是插入顺序的最后一个任务，不是时间上真正相邻的前驱。

**后果**：换型是离散制造最高频的约束之一。它不成立，"硬约束零违反"就只覆盖了资源互斥与工序顺序两条——而这两条由构造过程自动满足，等于没有校验。压测中 951 个任务的换型时间合计 951 小时，加上加工 1048 小时已超出 7 天总产能 49%，校验器仍报 0 违反。

**修正**：换型作为独立占用块，先 commit setup 再 commit 加工；前驱取时间相邻任务；同族 setup 显式为 0；矩阵缺项报错而非默认 60；校验器增加第四条守恒断言（加工 + 换型 + 停机互不重叠、不越日历）。

---

### B2 · 工序不能跨班次，长工序被误判为产能不足

**证据**（已复现）：600 分钟工序、8 小时单班日历、资源完全空闲 → 输出 `CAP_005` 未排。

**根因**：`peek_slot` 要求 `start + need <= 窗口结束`，单个窗口装不下即失败，没有跨窗口累计。

**后果**：装夹、热处理、老化、大件机加普遍超过 8 小时。P0 上线第一天就会把大批订单判成"产能不足"，且原因码指向错误方向，计划员无法自助定位。GB-05"吸附到班次边界"与"工序可跨班次"语义也直接冲突。

**修正**：工时改为"在日历内累计消耗"，slot 返回分段占用（`plan_task_segment`）；明确"加工可跨班次，换型必须整段落在工作时段"；甘特吸附改为吸附到工作时段起点。

---

### B3 · 订单非原子排产，未排订单仍占用产能，校验器看不见

**证据**（已复现）：某工序失败时 `break`，此前已 commit 的工序不回收，订单又被记入未排。压测 951 个任务中 156 个（16.4%）属于最终未排订单。

**根因**：无订单级事务；`validate()` 用 `if c in got` 过滤掉缺失工序，导致"部分排上"永远不触发顺序错误。

**后果**：虚高负荷、压低准时率；"硬约束违反数 = 0"成为同义反复。

**修正**：订单级暂存，全部工序成功才统一 commit，失败整单回滚并输出第一个卡点；校验器不得过滤缺失工序，新增"订单完整排产率"指标。

---

### B4 · 未排原因码没有存储落点，SC-08 / AN-03 无法实现

**位置**：`plan_task_trace.task_id` 是主键且外键指向 `plan_task`；未排订单没有 `plan_task` 行，原因码无处挂。

**后果**："未排订单 100% 带原因码"这条验收在现有 DDL 下不可能通过。且三处码表不一致：原型 5 个码、代码 3 个、技术方案示例 `ORD_001`。

**修正**：新增 `plan_unscheduled`（run_id、order_id、op_seq、level、reason_code、blocking_resource、earliest_feasible_ts、suggestion）与 `dict_reason_code` 字典表；码表按卡点层分族，API 提供枚举，全端引用同一份定义。

---

### B5 · "锁定 + 冻结区"与"P0 不做增量重排"自相矛盾

**位置**：清单 GB-07 与 E4 验收要求"锁定任务重排后位置不变"，但 §1.3 明确 P0 不做增量重排，`EngineInput` 里也没有任何已排任务入参。

**后果**：全量重排要保证锁定项不动、冻结区只允许排在其后，本质就是"固定任务占位 + 空隙插入"，即增量排产。当前设计无法实现该 Must，E3 的 43 人日也未包含这部分。

**修正**：二选一——(a) 承认 P0 必做固定任务占位，`EngineInput` 增加 `fixedTasks`，E3 +15 人日并重排 M2；(b) 锁定与冻结降为 P1，P0 只做"发布即冻结成只读版本"。

---

### B6 · DDL 缺 8 类必需表，E5/E7 的一半 Must 无存储落点

**缺失**：`sys_user/role/user_role/data_scope`、`audit_log`、`plan_approval`、`plan_publish`、`dispatch_record`、`plan_unscheduled`、`md_bom`、`inv_stock`、`md_alt_resource/md_alt_routing`。

**后果**：PB-03 审批、PB-04 下达、PB-05 发布记录、PF-01~04（17 人日）全部无处落；OR-06 齐套需要 BOM 与库存来源表；MD-03 替代路线、MD-02 替代资源只有能力标签，表达不了替代关系。`audit_log` 只出现在 §8 文字里。

---

### B7 · "物料齐套时点"与"模具唯一占用"在当前模型上不可实现

**位置**：`ord_production_order.material_ready_ts` 是订单级单值；`plan_task.resource_id` 只支持单资源；`md_operation.resource_group` 单能力标签。

**后果**：物料缺口是"物料 × 工序"粒度，订单级单值会让 OP30 才需要的长周期件把整单从 OP10 挡住；模具是独立资源，单 `resource_id` 建模不了"CNC + 操作工 + 模具"同时占用。宣称的 5 类硬约束实际只能做 2 类。

**修正**：`plan_task_resource(task_id, resource_id, role, qty)` 支持多资源占用；`ord_material_requirement` 增加 `at_op_seq`；SC-04 验收按实际可校验的约束逐条列，不笼统写"5 类"。

## 3. 重要问题

| ID | 问题 | 修正方向 |
|---|---|---|
| I1 | 订单状态机与计划版本状态互相污染；版本回滚与"已下达"无规则，可能出现两版计划同时执行 | 出状态迁移表；订单"已排/已发布"改为派生；加 `UNIQUE(plant_id,horizon_start) WHERE status='PUBLISHED'`；回滚区分是否已下达 |
| I2 | 幂等只有承诺没有约束：`src_system/src_id` 无 UNIQUE；发起排产无幂等键，双击产生两个并发批次 | 补唯一约束、单飞约束、`Idempotency-Key`；明确取消语义 |
| I3 | 全库无 `plant_id/workshop_id`，PF-02 行级权限无处注入，P2 多工厂要改全库 | 关键表补组织列，P0 填固定值 |
| I4 | 接口覆盖不到一半 Must，至少缺 12 处；`PATCH` 返回语义未定义 | 做 46 项 Must × 接口 × 表 × 页面追溯矩阵；`PATCH` 明确 `mode=check|commit` 与返回结构 |
| I5 | 快照只存哈希，历史不可回放；`plan_task` 不冗余业务字段，重同步后语义漂移 | 加输入快照表与主数据版本；`plan_task` 冗余不可变字段；发布后禁改 |
| I6 | 倒排、min_batch、capacity、efficiency 有声明无实现 | P0 要么实现要么删除；`duration = ceil(qty×std_time/efficiency)`；capacity>1 明确为并行槽位或拆机台 |
| I7 | 人日明细与汇总不符（重算 195 vs 表 196，E1/E4/E7 三项对不上）；甘特与引擎两个最不确定模块明显偏低；团队口径 5 人 / 6 人矛盾 | 汇总改自动求和；E4、SC-02 给区间并加 20% 缓冲；重报周期 |
| I8 | 甘特 300ms / 5000 块被三个未决问题拖住：拖拽语义、换资源换型差量、1 万任务接口无上限 | 明确"单任务试算、冲突拒绝、不自动级联"；换资源纳入前后邻居 setup 差量；接口加时间窗与行数上限 |
| I9 | 三套功能域划分互不对应（架构图 / 章节 / Epic），需求无法双向追溯 | 以一章为唯一划分，图、Epic、菜单、接口前缀对齐 |
| I10 | 原型数据自相矛盾：同版本"硬约束违反 2"与"0 违反"并存；工时与排程时长差 2–4 倍；任务块落在非工作时段；停用资源仍在甘特；日期"周三/周一"冲突；CNC 冲突建议换 SMT | 用一套样例数据把数字算自洽，或页头明确标注"布局示意"；至少统一冲突数、移除停用资源 |

## 4. 建议项

- **S1**：`md_shift` 的 `TIME/TIME` 无法表达跨夜班与加班；需 `cross_midnight` 或相对分钟数，并增加日历例外表（加班/半天/临时开线）。
- **S2**：多条验收不可测量。"结果稳定（或差异可解释）"无法判定且当前无最终 tie-breaker；"取消后资源立即释放"在测不存在的对象；"5000 资源"不符合单厂实际。改为可执行判定，规模按真实工厂量级。
- **S3**：原型与清单双向不一致。清单有原型无至少 13 项（MD-08/09/10、SC-07、GB-08、PB-04/05、OR-05、PF-01~04、AN-05）；原型有清单无 3 项（批量指派、保存模板、保存草稿）。PF 四个 Must 无原型、无接口、无表，是最大黑洞。
- **S4**：产品设计与技术方案两份数据模型并存且已发散（SalesOrder/PlannedOrder 无表、DecisionTrace 与 plan_task_trace 命名不一）。以 DDL 为单一事实源。

## 5. 修正计划与工期影响

### 5.1 修正顺序（有依赖）

```
第一批（决定 P0 承诺是否成立）
  B1 换型占位 + B2 跨班次 + B3 订单原子性 + 校验器守恒断言
  → 重跑压测，硬约束零违反才可信

第二批（决定范围与数据）
  B5 锁定/冻结二选一 → B6 补表 → B7 多资源与工序级齐套
  → B4 同时完成未排原因落点

第三批（决定能否交付）
  I2 幂等 → I3 组织维度 → I4 接口补齐 → I5 快照 → I8 甘特语义
```

### 5.2 工期重估

| 方案 | 内容 | 人日 | 周期（6 人） |
|---|---|---|---|
| A · 保范围 | 修正全部 B + I，锁定/冻结、倒排、模具约束全做 | 270–300 | 18–22 周 |
| B · 保周期 | 修正 B1–B4、B6；锁定/冻结、倒排、模具约束、capacity 并行降到 P1 | 210–230 | 15–17 周 |

**建议取 B**。但 B2（跨班次）**不能降级**——它是正确性问题，不是范围问题，降级会让系统在第一个长工序上就失效。

原 196 人日 / 13–16 周不宜再对外承诺。

---

## 6. 评审结论

**不能进入实现。**

B1、B2、B3 决定"硬约束零违反"这个 P0 核心承诺是否成立；B5、B6、B7 决定范围与工期。这六项修正完成、压测重跑通过后，才具备开工条件。

已确认无需返工的部分：技术选型、甘特 Canvas 路线、分层架构、API 风格、以及"先跑算法原型再写工程代码"的做法本身——正是原型让 B1–B3 在写 Java 之前暴露出来。

## 7. 修正进展（2026-11-18）

### 已修正并在原型中验证

| 项 | 状态 | 证据 |
|---|---|---|
| B1 换型不占位 | 已修正 | 换型作为独立区间 commit；前驱取时间相邻任务；同族 0 换型。用例：A1 08:00–09:00，FA→FB 换型占 09:00–10:00，B1 加工 10:00 起 |
| B2 工序不能跨班次 | 已修正 | `peek_span` 在日历内累计消耗并产出多段占用。用例：600 分钟工序在 8h 单班下跨 2 段完成，不再误判 CAP_005 |
| B3 订单非原子 | 已修正 | 逐单暂存、失败整单回滚。用例：第二道工序排不下时，第一道不残留，空闲区间完整还原 |
| 校验器自证 | 已修正 | 新增时间轴守恒（加工+换型不重叠、不越日历、换型不跨班次）与“订单未完整排产”断言；负向用例可检出人为注入的重叠 |
| I6 字段无行为 | 部分修正 | `duration = ceil(max(qty,min_batch) × std_time / efficiency)` 已落地；`capacity>1` 显式拒绝并要求拆机台 |

v2 原型：5 个回归用例全部通过；1500 任务压测 212ms，硬约束 0 违反。
