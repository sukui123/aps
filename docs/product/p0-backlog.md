# APS 排产系统 · P0 功能清单与验收标准

> 版本：v0.1
> 对应设计：[APS 排产系统 · 产品设计](./aps-product-design.md) 第 7 章 P0
> 目标：交付一个**可用的排产闭环**——能导入真实订单、排出满足硬约束的可行计划、计划员能手工调整、能发布下达。
> 周期估算：13～16 周（后端 3 人 + 前端 2 人 + 测试 1 人）
> 原型：`docs/prototype/p0-prototype.html`

---

## 1. P0 范围定义

### 1.1 一句话目标

> 用真实一周订单，在有限产能下排出工序级计划，硬约束零违反，计划员可在甘特上调整并发布下达。

### 1.2 必须包含（Must）

- 主数据可维护、可导入、可校验
- 订单可接入、可筛选、可维护优先级
- 有限产能全量排产（启发式），硬约束校验
- 资源泳道甘特，可拖拽、可手工插单（锁定 / 冻结区在 P1）
- 计划版本发布 + 审批 + 工单下达
- 基础的未排清单、负荷分析、KPI

### 1.3 明确不做（Out of Scope）

| 不做 | 原因 | 何时做 |
|---|---|---|
| 增量/局部重排 | P0 先跑通全量闭环 | P1 |
| 锁定 / 冻结区 | 需要固定任务占位与插入，本质就是增量排产，与 P0 范围冲突；P0 的「冻结」只做发布后版本只读 | P1 |
| 多方案比选、CTP 模拟 | 依赖引擎稳定 | P1 |
| 决策轨迹与订单追踪 | 需要引擎埋点，先留数据结构 | P1 |
| 优化求解器（CP-SAT） | 启发式已可满足可行性 | P2 |
| 换型矩阵自动学习 | 先手工维护 | P2 |
| 多工厂协同 | 单工厂先跑通 | P2 |
| 移动端、大屏 | 非核心链路 | P2 |
| MRP / 采购建议 | 边界外 | 不做 |

## 2. Epic 与功能清单

优先级：**M**=Must（P0 必须）；**S**=Should（P0 争取，可延后一版）
估算单位：人日（含前后端联调，不含测试用例编写）

| MD-06 | 换型矩阵 | 资源维度的 A→B 换型时间、同族免换型 | M | 3 |
| MD-07 | 工厂日历与班次 | 班次模板、工作日、节假日、加班 | M | 4 |

- 能从 Excel 一次性导入 ≥5000 条资源、≥2000 条工艺路线，错误行精确定位到行号与字段。
- 停用的资源不再出现在排产候选中。
- 日历修改后，新排产结果中的工作时间随之变化。

### E3 · 排产引擎与任务（Must）

| ID | 功能 | 说明 | 优先级 | 估算 |
|---|---|---|---|---|
| SC-01 | 排产参数配置 | 计划时间范围、正/倒排、目标权重、资源范围 | M | 4 |
| SC-02 | 全量排产执行 | 异步任务，启发式求解，产出计划与决策记录 | M | 15 |
| SC-03 | 任务进度与日志 | 进度百分比、阶段、耗时、失败原因、可取消 | M | 3 |
| SC-04 | 硬约束校验 | 工序顺序、资源互斥、日历、物料齐套、模具唯一 | M | 6 |
| SC-05 | 软约束计分 | 延期、换型、负荷不均衡，输出方案得分 | M | 4 |
| SC-06 | 批次与版本 | 每次排产生成 PlanRun + PlanVersion，可追溯 | M | 4 |
| SC-07 | 版本回滚 | 回滚到上一发布版本 | M | 2 |
| SC-08 | 未排原因输出 | 每张未排订单输出卡点层级与原因码 | M | 5 |
| SC-09 | 引擎可配置 | 约束启停、优先级规则参数化 | S | 5 |

**验收（E3）**
- 1 万道工序全量排产 ≤5 分钟，硬约束违反数 = 0。
- 同一输入重复排产，结果稳定（相同参数下结果一致或差异可解释）。
- 取消任务后资源立即释放，不残留锁。
- 未排订单 100% 带原因码，原因码可枚举。

- 发布后计划版本不可编辑，需基于新版本调整。

## 5. 接口清单

完整的 P0 接口契约（约 70 个端点，按域分组、含写操作语义与幂等约定）见
[技术方案 §5](../tech/technical-design.md#52-接口清单p0-完整版)，
功能 ↔ 页面 ↔ 接口 ↔ 数据表的逐一对应见
[P0 需求追溯矩阵](./traceability-matrix.md)。

本文件不再维护第二份接口列表，避免两处口径发散。关键写接口约定：

| 接口 | 约定 |
|---|---|
| `POST /scheduling/runs` | 必须带 `Idempotency-Key`；同工厂同时只允许一个 RUNNING/QUEUED |
| `PATCH /plans/{id}/tasks/{taskId}` | `?mode=check\|commit`；单任务试算、冲突拒绝、不自动级联 |
| `POST /plans/{id}/publish` | 前置：审批通过 + 校验无阻断；发布后版本冻结 |
| `POST /plans/{id}/dispatch` | 必须带 `Idempotency-Key`，失败可重试不产生重复工单 |

| 里程碑 | 内容 | 周期 | 出口标准 |

## 7. 关键风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 客户主数据质量差 | 排不出可用计划，项目停摆 | P0 内置数据体检 + 导入校验，实施前置清洗 |
| 引擎性能不达标 | 计划员等待过久弃用 | 早期用真实量级数据压测，先做资源索引与增量计算 |
| 甘特交互复杂度被低估 | 拖拽体验差，退回 Excel | 预留 2 周专项，先做只读甘特再上拖拽 |
| 约束表达不清导致反复改代码 | 工期失控 | 约束用配置表驱动，P0 只做 5 类硬约束 |
| 与 ERP 接口反复 | 集成延期 | 先做文件/视图同步兜底，接口后置 |

## 8. 验收总清单（P0 交付判定）

- [ ] 导入 5000 资源 / 2000 工艺路线 / 1 万订单，无阻断错误
- [ ] 1 万道工序全量排产 ≤5 分钟
- [ ] 硬约束违反数 = 0
- [ ] 未排订单 100% 带原因码
- [ ] 甘特 5000 任务块渲染 ≤1.5 秒
- [ ] 拖拽调整 300ms 内返回校验
- [ ] 发布前三项校验全部拦截
- [ ] 下达 MES 幂等，失败可重试
- [ ] 全流程操作可审计
