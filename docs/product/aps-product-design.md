## 1. 产品定位与边界

### 1.1 在制造计划体系中的位置

```
销售订单/预测
      │
      ▼
   ERP（订单、库存、财务）
      │
      ▼
   MRP（物料需求计划，无限产能倒排）
      │  生产订单 + 物料需求时点
      ▼
   APS（有限产能、工序级排程）   ◀── 本产品
      │  工单下达时间、工序级开工/完工、资源分配
      ▼
   MES（执行、报工、设备状态）
      │  实绩反馈
      └──────────────► 回写 ERP / 触发滚动重排
```

**一句话定位**：在有限产能和多重工艺约束下，把生产订单翻译成"哪台设备、在什么时间、按什么顺序、做哪道工序"的可执行计划，并对变化做出快速、稳定的重排。

### 1.2 解决什么问题

| 解决 | 不解决 |
|---|---|
| 有限产能下的工序级排程 | 物料采购计划（属 MRP/ERP） |
| 交期可行性评估与承诺（CTP） | 财务成本核算 |
| 换型、模具、技能、日历等复杂约束 | 车间级实时调度（属 MES/高级排程执行） |
| 插单/改单/设备故障后的快速重排 | 工艺设计与 BOM 编制（属 PLM/ERP） |
| 计划可解释、可人工干预、可多方案比选 | 全厂级 S&OP 战略规划 |

### 1.3 与"排查/可解释"的关系

排产结果不可解释是 APS 落地的头号障碍。因此**可解释性不是附加功能，而是引擎的一等输出**：每次排产必须产出决策依据（为什么用这台设备、为什么这个时间、被哪条约束限制），并对外提供"订单追踪"能力。详见 4.7 与 6.4。

## 2. 目标客户与典型场景

### 2.1 行业适配

| 行业类型 | 适配度 | 关键约束 |
|---|---|---|
| 离散制造 · 多品种小批量（装备、电子装配、医疗器械） | ★★★★★ 首选 | 工艺路线、替代资源、换型、齐套 |
| 汽车零部件 / 汽配 | ★★★★☆ | 节拍、看板、JIT、模具 |
| 流程行业（化工、食品、制药） | ★★☆☆☆ | 配方、批次、罐容、清洗切换，需专门建模 |
| 项目型制造（大型装备、船舶） | ★★★☆☆ | 网络计划、长周期、关键路径 |

**策略建议**：先打透一个离散制造细分行业，用配置覆盖共性，避免"通用到不能用"。

### 2.2 典型业务场景

1. **周计划编制**：每周拉取订单，跑一次全量排产，评审后发布。
2. **日计划调整**：插急单、设备故障、缺料，做局部重排。
3. **交期承诺**：销售询单时，模拟插入看是否可满足交期（CTP）。
4. **产能评估**：新增订单前评估瓶颈工序负荷。
5. **计划稳定性治理**：控制重排导致的大幅变动。

### 2.3 用户角色

| 角色 | 核心诉求 | 主要功能 |
|---|---|---|
| 主计划员 / PMC | 快速得到可行计划、少手工调 | 排产工作台、甘特、方案比选 |
| 车间计划员 / 调度 | 日计划可执行、能应对现场变化 | 日计划、派工、局部重排 |
| 生产经理 | 交期达成、产能利用、稳定 | 审批、KPI 看板 |
| 销售 / 客服 | 交期可承诺 | CTP 模拟、订单跟踪 |
| 实施 / 算法工程师 | 规则可配置、问题可定位 | 规则配置、数据校验、排查工具 |
| IT / 集成 | 接口稳定、可运维 | 集成管理、监控、审计 |

## 3. 核心业务对象与数据模型

### 3.1 实体清单

| 域 | 实体 | 关键属性 | 来源 |
|---|---|---|---|
| 需求 | 销售订单 SalesOrder | 客户、交期、优先级、数量 | ERP/CRM |
| 需求 | 生产订单 ProductionOrder | 物料、数量、需求日期、状态 | ERP/MRP |
| 需求 | 计划订单 PlannedOrder | 建议开工/完工、来源需求 | APS 生成 |
| 工艺 | 物料 Item | 编码、单位、批量规则、提前期 | ERP/PLM |
| 工艺 | BOM | 父子件、用量、替代料、有效版本 | ERP/PLM |
| 工艺 | 工艺路线 Routing | 工序序列、工序关系（串/并/网络） | PLM/ERP |
| 工艺 | 工序 Operation | 标准工时、准备时间、可选资源组 | PLM |
| 资源 | 工作中心 WorkCenter | 产能、并行度、所属车间 | 主数据 |
| 资源 | 设备/机台 Machine | 能力、状态、维护计划 | 主数据/MES |
| 资源 | 线体 Line | 节拍、共线产品族 | 主数据 |
| 资源 | 模具/工装 Tool | 可用性、寿命、换装时间 | 主数据 |
| 资源 | 人员/班组 Crew | 技能矩阵、班次、出勤 | HR/主数据 |
| 日历 | 工厂日历 Calendar | 工作日、班次、节假日 | 主数据 |
| 日历 | 停机/维护 Downtime | 时段、资源、原因 | MES/主数据 |
| 约束 | 换型矩阵 SetupMatrix | 从 A 到 B 的换型时间 | 主数据（可学习） |
| 约束 | 约束规则 ConstraintRule | 类型、硬/软、参数、作用域 | 配置 |
| 计划 | 排产批次 PlanRun | 参数快照、引擎版本、耗时、状态 | APS |
| 计划 | 计划版本 PlanVersion | 版本号、基线、发布状态 | APS |
| 计划 | 排产任务 ScheduledTask | 订单+工序+资源+开始/结束+锁定态 | APS |
| 计划 | 决策依据 DecisionTrace | 候选资源、过滤原因、约束命中 | APS |

### 3.2 关键关系

```
SalesOrder 1─n ProductionOrder 1─n Operation(按 Routing 展开)
                                    │
                                    ├─n 候选资源组 ─n WorkCenter/Machine
                                    └─n ScheduledTask（排产后）
ScheduledTask n─1 Resource，n─1 PlanVersion
PlanVersion n─1 PlanRun（参数与输入快照）
DecisionTrace n─1 ScheduledTask
```

### 3.3 数据模型的三条硬要求

1. **版本化**：主数据、订单、计划全部带有效期与版本，否则无法复现历史排产。
2. **快照化**：每次 PlanRun 冻结一份输入快照，保证"当时为什么这么排"可回放。
3. **可追溯**：计划行必须能反查来源订单、工艺路线版本、命中的约束与规则。

### 4.4 排产引擎（核心）

#### 4.4.1 约束体系（三级）

| 级别 | 含义 | 示例 |
|---|---|---|
| 硬约束 | 违反即不可行 | 工序顺序、资源互斥、日历不可用、物料齐套、模具唯一 |
| 软约束 | 违反计惩罚分 | 交期延误、换型次数、负荷不均衡、WIP 过高 |
| 偏好 | 影响排序/选择 | 优先同族连续、优先低负荷设备、优先就近工序 |

#### 4.4.2 排产模式

| 模式 | 场景 | 特点 |
|---|---|---|
| 全量排产 | 周计划 | 重新求解全部订单，结果最优化但变动大 |
| 增量排产 | 日常插单 | 保留已排结果，只排新单/变更单 |
| 局部重排 | 设备故障、缺料 | 指定资源/时间窗/订单集合重排 |
| 模拟排产 | 方案比选、CTP | 沙箱执行，不影响正式计划 |

#### 4.4.3 求解策略

- **启发式（规则驱动）**：优先保证可行、快速、可解释。适合万级工序的分钟级响应，是产品默认路径。
- **约束规划/优化求解**：CP-SAT 等，用于关键订单集合或收尾优化，提升交期达成与换型优化。
- **混合**：启发式生成初始解 → 优化器局部改进 → 硬约束校验兜底。
- **可中断**：长求解支持时限与进度反馈，超时返回当前最优可行解并标注"未收敛"。

#### 4.4.4 目标函数

多目标加权，权重可按工厂/计划类型配置：

```
min  Σ w1·延期时长 + w2·换型次数 + w3·WIP + w4·负荷方差 + w5·计划变动量
s.t. 硬约束全部满足
```

计划变动量（nervousness）单独加权，是稳定性的关键杠杆。

#### 4.4.5 可解释输出

每个 ScheduledTask 输出：

- 候选资源集合及被排除原因（能力不符/无日历/物料未齐/被更高优先级占用）
- 命中的约束与规则清单
- 与上一版计划的差异及原因
- 若未排上：卡在哪一层、缺什么、需要什么才能排上

## 5. 端到端业务流程

```
① 订单接入         ERP 同步/导入 → 订单池
② 齐套与可行性      物料齐套、工艺完整、资源可用校验
③ 排产参数         选择策略、时间范围、冻结区、目标权重
④ 求解             启发式/优化，产出计划与决策轨迹
⑤ 结果校验         硬约束校验、冲突清单、未排清单
⑥ 人工微调         甘特拖拽、锁定、插单、方案比选
⑦ 评审发布         多级审批 → 生成工单 → 下达 MES / 回写 ERP
⑧ 执行跟踪         报工回采、偏差监控、异常处理
⑨ 滚动重排         事件/周期触发，回到 ③
⑩ 复盘沉淀         指标分析、案例入库、规则调优
```

## 6. 关键产品决策

| 决策点 | 建议 | 理由 |
|---|---|---|
| 产品化 vs 项目化 | 配置驱动，规则不写死 | 每个客户约束不同，改代码即失去产品价值 |
| 启发式 vs 优化求解 | 启发式为默认，优化为增强 | 可解释、响应快，落地成功率高 |
| 排产粒度 | 工序级 | 工单级无法处理换型与资源分配，价值不足 |
| 是否做 MRP | 不做，专注排程 | 边界清晰，避免与 ERP 正面冲突 |
| 自研 vs 第三方求解器 | 业务层自研 + 开源求解器（OR-Tools/Timefold） | 降低算法风险，聚焦业务建模 |
| 行业策略 | 先打透一个离散行业 | 通用产品在排产领域几乎不可用 |
| 可解释性 | 一等公民，引擎直接输出 | 决定用户信任与实施周期 |
| 计划稳定性 | 变更惩罚 + 冻结区 | 计划频繁抖动会让车间放弃使用系统 |

## 7. 迭代路线

### P0 · 可用闭环（MVP）

- 主数据建模（资源、工艺、日历、换型基础）
- 订单接入与订单池
- 有限产能启发式排产（正排 + 硬约束）
- 甘特工作台（查看、拖拽、锁定）
- 计划发布与工单下达
- 基础负荷分析与未排清单

**验收**：能对真实一周订单产出可行计划，硬约束零违反，计划员可手工调整并发布。

### P1 · 好用与稳定

- 约束与目标可配置（软约束、权重）
- 增量排产与局部重排、冻结区
- 多方案比选、CTP 模拟
- 决策轨迹与订单追踪（可解释）
- 版本对比与计划稳定性指标
- 执行回采与偏差分析

**验收**：日常插单 5 分钟内完成重排；90% 的未排单可自助定位原因。

### P2 · 智能与规模化

- 优化求解器增强（交期与换型联合优化）
- 换型时间学习、工时校准
- 多工厂协同、跨厂调拨
- 异常智能归因与处置建议
- 开放平台与行业模板

## 8. 非功能需求

| 维度 | 目标 |
|---|---|
| 性能 | 1 万工序全量排产 ≤ 5 分钟；10 万工序 ≤ 60 分钟；增量排产 ≤ 30 秒 |
| 并发 | 支持多工厂并行排产，任务队列隔离 |
